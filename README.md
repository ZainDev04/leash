# Leash

Leash lets AI agents pay through PayPal, but only inside rules you set.

You save your PayPal once. After that, an agent can ask Leash to pay for something while you are away. Leash runs every payment through the same steps:

1. Leash reads the shop page itself from a store on your verified list and compares the price and seller with what the agent claims. A payment without a page Leash could read waits for you.
2. Fixed code checks: per-payment limit, monthly budget, allowed categories, allowed and blocked stores, currency, price changed since the quote, the same purchase twice in 10 minutes, and the freeze switch.
3. If those pass, Leash puts the money on hold in PayPal (an authorization, nothing is taken yet).
4. Gemini reads the shop page and the user's original task. It looks for hidden instructions aimed at AI agents and checks that the item fits the task.
5. Leash then captures the payment, keeps the hold and asks you, or voids the hold.

The AI can only make a decision stricter. It can never approve something the code checks reject. If Gemini or PayPal fails, Leash blocks the payment.

Built for the PayPal AI Hackathon 2026. PayPal sandbox only, no real money.

Live demo: https://leash-b2xx.onrender.com (the first request after a quiet spell can take about a minute).

## How PayPal is used

All PayPal calls go through the official PayPal Server SDK for Python (`paypal-server-sdk`, generated by APIMatic), fixed to the sandbox.

- Orders v2 with intent `AUTHORIZE` to hold money before the checks finish
- Vault (`store_in_vault: ON_SUCCESS`) so the user approves once and agents can pay later with no click
- Authorizations v2 capture and void to pay or release the hold

## How AI is used

- Google Gemini (`gemini-3.5-flash`) checks each payment that passes the code checks: hidden instructions in the page, item vs task, and a plain-English reason for the user.
- Gemini turns rules written in plain English into the policy JSON. Leash shows a summary and only saves it after the user confirms.

## Run it

You need Python 3.11 or newer, a PayPal developer account and a Gemini API key.

1. PayPal sandbox app
   - Log in at https://developer.paypal.com, switch to Sandbox, open Apps & Credentials and create an app (type Merchant).
   - In the app's features, turn on Vault (save payment methods).
   - Under Testing Tools > Sandbox Accounts, note the Personal account's email and password. You log in with it when saving PayPal.
2. Gemini key from https://aistudio.google.com
3. Set up:
   ```
   git clone https://github.com/ZainDev04/leash.git
   cd leash
   python -m venv .venv
   .venv/Scripts/pip install -r backend/requirements.txt   # Mac/Linux: .venv/bin/pip
   cp .env.example .env
   ```
   Fill in `.env`:
   - `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` and `LLM_API_KEY`
   - `LEASH_ADMIN_PASSWORD`: your dashboard password, at least 12 characters
   - `LEASH_AGENT_KEYS`: one key per agent, for example `claude:KEY1,demo-shopper:KEY2`. Make a key with `python -c "import secrets; print(secrets.token_urlsafe(32))"`
   - `LEASH_API_KEY`: the demo agent's key (`KEY2` in that example)
4. Start Leash:
   ```
   .venv/Scripts/uvicorn backend.main:app --port 8000
   ```
5. Open http://localhost:8000/app and log in with your dashboard password. Click "Connect PayPal", log in with the sandbox Personal account and approve. A $1 hold is placed and released at once.
6. Optional: type your own rules in plain English, click "Read my rules", check the summary and confirm.
7. Run a real AI agent in a second terminal and watch the dashboard:
   ```
   .venv/Scripts/python agents/shopper.py "Buy me a beginner Python book under 30 dollars"
   ```
   Gemini reads the demo store at http://localhost:8000/store, picks a book and pays through Leash. The agent gets no warning about hidden instructions, so the safety comes from Leash. One purchase uses about six calls from the Gemini free quota.

   `agents/demo_shopper.py` is a scripted version that needs almost no quota. It makes four purchases: one is paid, one waits for your approval, one is blocked because the price went up, and one is blocked because the shop page hides instructions for AI agents.

## Audit log

The dashboard keeps every payment an agent tried in an [AG Grid](https://www.ag-grid.com/) table: what was asked for, what Leash decided, who decided it and why.

- Filter by result, search every column (PayPal IDs too), or filter and sort each column.
- The bottom row adds up the money really taken for the rows in view, so filtering by agent or date answers "how much did this agent spend?".
- Click a row for the full reasons, the task and the PayPal order, hold and capture IDs.
- Export CSV for the rows in view. Item names come from agents and shops, so text that a spreadsheet would run as a formula is made safe first.

AG Grid Community (MIT) is served from `frontend/static/vendor`, because the site's security policy loads scripts only from its own address.

## Shop through Leash from Claude (MCP)

`mcp_server/server.py` gives an MCP client four tools: `read_shop_page`, `pay`, `check_budget` and `check_payment`. The agent's key only reaches payments and rules it can read, so the agent cannot approve a payment, change the rules or lift the freeze.

Start the backend first (step 4 above), then add the server. Use the full path to your copy of the repo and a key from `LEASH_AGENT_KEYS`.

Claude Code:
```
claude mcp add leash -e LEASH_API_KEY=your-agent-key -- /full/path/to/leash/.venv/Scripts/python /full/path/to/leash/mcp_server/server.py
```

Claude Desktop, in `claude_desktop_config.json`:
```json
{
  "mcpServers": {
    "leash": {
      "command": "/full/path/to/leash/.venv/Scripts/python",
      "args": ["/full/path/to/leash/mcp_server/server.py"],
      "env": { "LEASH_API_KEY": "your-agent-key" }
    }
  }
}
```

On Mac or Linux the Python path ends in `.venv/bin/python`. Set `LEASH_URL` if the backend is not on `http://localhost:8000`. The name shown on the dashboard comes from the key.

Then ask Claude to buy a book from the demo store. The payment appears on the dashboard.

## API

Agents send `Authorization: Bearer <key>`:

- `POST /pay`: merchant, item, category, amount, currency, quoted_price, task, product_url, page_text. Returns the payment with status `paid`, `waiting` or `blocked` and the reasons.
- `GET /status`, `GET /payments/{id}`

These need the dashboard login:

- `GET /payments`, `POST /payments/{id}/approve`, `POST /payments/{id}/reject`
- `POST /policy/parse` (plain English in, draft rules out), `PUT /policy`
- `POST /freeze`, `POST /unfreeze`
- `GET /vault/start` (save PayPal)

Open to anyone: `/` (home page), `/store` (demo store), `/login`, `/health`, `/ready`, `/robots.txt`, `/sitemap.xml`.

## Security and running it in production

- Dashboard login uses a signed, HttpOnly cookie. Login attempts, payments and rule parsing are rate limited.
- Changes from another website are refused, and every response carries security headers, including a Content-Security-Policy with no inline scripts.
- Payments that arrive at the same moment cannot share the same unspent budget, and a double click on Approve can only capture once. If capture fails, the hold is voided.
- Logs are one JSON line per request with a request ID. `/health` says the process is up and `/ready` says it can reach the database.
- When hosted on an `https://` address, secure cookies and HSTS turn on. Render's address is picked up by itself. Elsewhere, set `PUBLIC_URL`.
- PayPal calls retry on temporary errors. Each change carries a request ID, so a retry cannot pay twice.
- A payment left unfinished by a server crash is closed and its hold released.

## Deploy and scale

`render.yaml` deploys the app on Render (New > Blueprint). Paste a Postgres address as `DATABASE_URL`, your PayPal and Gemini keys, a dashboard password and `LEASH_AGENT_KEYS` when asked, then open the site and connect PayPal. The live demo keeps its data on the Neon free plan, which does not expire. Use the direct address from Neon, not the pooled one.

Sessions, rate limits and rules live in signed cookies or the database, so any copy of the server can answer any request. To run several copies behind Render's load balancer, use a paid plan and set `numInstances` in `render.yaml`. The load balancer stops sending traffic to a copy when its `/ready` check fails.

`tests/test_two_copies.py` runs two copies as separate processes and sends requests to them in turn. It checks that the budget, repeat check, kill switch, login and rate limits hold across both, that Approve captures once, and that the second copy keeps working when the first one dies. CI runs it on SQLite and on real Postgres. Free Render services sleep when idle, so the first request after a quiet spell can take about a minute.

## Tests

```
.venv/Scripts/pip install -r backend/requirements-dev.txt
.venv/Scripts/python -m pytest
```

The tests use a fake PayPal and a fake Gemini, so they need no keys and no network. GitHub Actions runs them on every push.
